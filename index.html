Visão geral & metodologia

O banco do grupo na web

🌐 O grupo publica o banco no Supabase e fecha as tabelas com RLS. Cada integrante apresenta duas partes: (a) a VIEW com as colunas que podem ser públicas e (b) a página dashboard que lê a view com fetch.

Visão geral & metodologia

O caminho de um dado

A página nunca toca uma tabela: pede à API, a API consulta a view, e só a view lê as tabelas.

🖥️ Página do integrante · HTML + JS com fetch e chave publicável
↓ HTTP GET
⚡ API REST do Supabase · PostgREST traduz a URL em SQL
↓ SELECT
👁️ vw_dash_… · aberta à leitura com GRANT SELECT … TO anon
↓ JOIN
🔒 Tabelas do banco · RLS ligada, sem política
Grupo · Segurança

🔒 RLS fechada, views abertas

ALTER TABLE aluno    ENABLE ROW LEVEL SECURITY;
ALTER TABLE presenca ENABLE ROW LEVEL SECURITY;
ALTER TABLE multa    ENABLE ROW LEVEL SECURITY;
-- ...todas as tabelas, sem CREATE POLICY

REVOKE ALL ON vw_dash_multa FROM anon, authenticated;
GRANT SELECT ON vw_dash_multa TO anon;

Por que views?

  • A RLS escolhe linhas; a view escolhe colunas.
  • Só entra na view o que pode ser público: toda coluna posta nela fica aberta.
  • A chave publicável vai no código; a secreta (service_role) nunca sai do servidor.

Evento Presença

🎒 vw_dash_presenca e vw_dash_aluno

(a) Views · sem CPF nem nome

CREATE VIEW vw_dash_presenca AS
SELECT p.fk_viagem_id AS viagem,
       p.data_presenca, a.serie
FROM presenca p
JOIN aluno a ON a.cpf = p.fk_aluno_cpf;

CREATE VIEW vw_dash_aluno AS
SELECT a.serie,
       COUNT(p.fk_viagem_id) AS total_presencas
FROM aluno a
LEFT JOIN presenca p ON p.fk_aluno_cpf = a.cpf
WHERE a.cpf IN (SELECT fk_aluno_cpf FROM inscrito)
GROUP BY a.cpf, a.serie;

GRANT SELECT ON vw_dash_presenca TO anon;
GRANT SELECT ON vw_dash_aluno TO anon;

O código e os prompts

⚡ O trecho que fala com o banco

const r = await fetch(`${URL}/vw_dash_multa?select=*`, {
  headers: { apikey: CHAVE,
             Authorization: `Bearer ${CHAVE}` } });
if (!r.ok) throw new Error(`HTTP ${r.status}`);
const dados = await r.json();
if (dados.length === 0) return mostrarVazio();

Só a chave publicável (sb_publishable_…) aparece no código.

🤖 Prompts usados no agente de IA

  • Estrutura: HTML único, CSS moderno e JS puro, com cartões de indicadores e ao menos 2 gráficos em Chart.js.
  • Estados: carregando, erro HTTP com try/catch e mensagem amigável, e lista vazia.
  • Segurança: só a chave pública no fetch; a service_role jamais no front-end.
  • Visual (presenças): painel acolhedor, tema escola, paleta do slide, em uma tela fixa sem rolagem.
Conclusão

Resumo & checklist da Etapa 7

🎓 O grupo comprovou na prática

  • Banco publicado no Supabase
  • RLS em todas as tabelas, sem política
  • Views por evento, com as colunas justificadas
  • GRANT SELECT … TO anon: só as views saem
  • 4 dashboards tratando carregando, erro HTTP e lista vazia

A página pode ser gerada por IA; o banco, não. Decidir quais colunas saem e garantir que nada mais sai é trabalho de quem projeta o banco.
